# 什么叫方法区别，什么叫实现区别

起因：对比我们跑的 MAGIC-Video 和上游时，我用"会不会改变模型看到的内容或最后的分数"当判据去分类，把换模型、换归一化函数、改阈值都列成了方法区别。用户指出这些都是实现区别。这个判据是错的，记录下正确的判据。

## 判据

方法区别：流程本身变了。多了或少了一个环节，某个环节的定义变了，控制流的走法变了。

实现区别：同一套流程，换参数或换组件。模型、embedding 模型、归一化函数、阈值、窗口大小、prompt 措辞、进程和状态的隔离方式，都属于这一类。

"会改变输出"不是方法区别的判据。换个模型输出一定会变，但算法没变。

## 按这个判据分类我们对 MAGIC-Video 的修改

方法区别：

- 时间检索分支加了提问时刻的截断。上游 `retrieve_by_time` 没有这个过滤环节，我们加了一个。
- 抽取失败时的控制流。上游吞掉异常返回空，这一轮退回普通检索继续；我们抛错并把错误交回模型让它改正，这一轮被消耗掉。

实现区别：

- 换模型（Qwen3.8-27B，reasoning xhigh）。
- 视觉查询的编码从 VLM2Vec-v2 折叠到文本 embedding 模型。
- chain 文本匹配的归一化从 `.lower()` 换成 NFKC + casefold + 合并空白。
- chain 注入参数与 vendored 默认值不同（min_hits 1 对 2，max_event_chains 1 对 2，两个相似度阈值 0.7 对 0.5）。
- 点时间窗口前后各 30 秒，上游模板例子是往后 60 秒。
- 时间抽取用同一个作答模型，上游写死另一个轻量模型。
- 每题重建 MagicMemory，上游复用同一个实例且索引只单调前进。
- 开放题把 QA 模板从四选一改写成开放式；MCQ 保留上游模板，选项放进题干并额外要求最后一行输出 `Answer:` 加字母。
- 事件链解析只认 EgoLife 的 `DAYn` 加 `HH:MM:SS`，删掉 MM-Lifelong 的浮点秒分支和 start 与 end 都为 0 就跳过的规则。对 EgoLife 流程没变，只是这份副本不能再跑 MM-Lifelong。
- 取帧改用 PyAV 加 clip-map 间接寻址；惰性导入；字典取值从 `get` 换成严格索引；缺文件和缺 embedding 从静默跳过改成报错；BM25 的 import 不再包在 try 里。

不算修改（和上游代码里的默认值一致）：top_k 16、alpha 0.7、seed_top_k 5、damping 0.85、bm25_weight 0.3、每段最多 16 帧、总共最多 64 帧、最多 5 轮、最多 5 次错误。
