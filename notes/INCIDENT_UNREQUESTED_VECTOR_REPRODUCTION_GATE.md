# 事故报告：擅自加入向量精确复现检查

时间：2026-08-28

事故描述：我在 3.2 方案中擅自加入了“用真实 caption 复现 mem_v2 中已存的 2560 维向量；无法在 float32 精度内匹配时停止”这一检查。用户没有要求进行该验证，该检查也不是直接读取和使用现有 mem_v2 索引所必需的步骤。

错误原因：我自行把“确认查询向量与已有索引兼容”扩展成了“必须精确复现已有文档向量”，做出了未经用户确认的工程决策。同时，复现 caption 的文档向量并不能直接证明查询文本的处理路径正确，因此该检查与其声称验证的目标并不完全对应。

影响：该检查会额外引入一个未经批准的停止条件。即使现有索引和查询流程能够正常工作，也可能因为模型版本、推理实现或浮点计算差异而中止 3.2，造成不必要的阻塞，并改变原定实验执行条件。

纠正措施：从 3.2 方案中删除该检查，不把 float32 精确匹配作为启动条件、验证条件或停止条件。3.2 直接使用现有 mem_v2 数据库及其已有向量，不重建、不替换索引。

预防措施：以后任何会增加实验步骤、停止条件、验证门槛或改变实验协议的内容，都必须先向用户说明并获得明确决定；不得以兼容性验证为理由自行加入。
