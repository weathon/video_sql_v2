Current formal infrastructure (disaggregated encoder)

The Qwen encoder runs on physical GPU 5. The Qwen prefill/decode service runs
on physical GPUs 0,2. The embedding service runs on physical GPU 4. All
containers use the project bridge network. Do not start containers with `--rm`;
stop them after the run, inspect their logs, and remove them manually.

Create the project network once:

docker network create video-sql-v2

Create the shared encoder-cache volume backed by tmpfs:

docker volume create \
    --driver local \
    --opt type=tmpfs \
    --opt device=tmpfs \
    video-sql-ec-cache

Build the EPD image whose ExampleConnector loads cache tensors on each TP
worker's current CUDA device:

docker build \
    -f infra/Dockerfile.vllm-epd \
    -t video-sql-vllm-epd:ec-tp-device \
    infra

Qwen/Qwen3.8-27B-FP8 encoder service:

docker run --name qwen38-27b-fp8-epd-encoder \
    --network video-sql-v2 \
    --gpus '"device=5"' \
    --shm-size=32g \
    -e HF_HOME=/hf_cache \
    -e VLLM_SERVER_DEV_MODE=1 \
    -v /raid/huggingface:/hf_cache \
    -v video-sql-ec-cache:/epd_shared/cache \
    video-sql-vllm-epd:ec-tp-device \
    Qwen/Qwen3.8-27B-FP8 \
    --host 0.0.0.0 \
    --port 8000 \
    --mm-encoder-only \
    --enforce-eager \
    --no-enable-prefix-caching \
    --gpu-memory-utilization 0.45 \
    --max-num-batched-tokens 114688 \
    --max-num-seqs 24 \
    --enable-request-id-headers \
    --ec-transfer-config '{"ec_connector":"ECExampleConnector","ec_role":"ec_producer","ec_connector_extra_config":{"shared_storage_path":"/epd_shared/cache"}}'

Qwen/Qwen3.8-27B-FP8 prefill/decode service:

docker run --name qwen38-27b-fp8-epd-pd \
    --network video-sql-v2 \
    --gpus '"device=0,2"' \
    --shm-size=32g \
    -e HF_HOME=/hf_cache \
    -e VLLM_ALLOW_LONG_MAX_MODEL_LEN=1 \
    -e VLLM_SERVER_DEV_MODE=1 \

    --host 0.0.0.0 \

Responses EPD proxy:

docker run --name qwen38-27b-fp8-epd-proxy \
    --network video-sql-v2 \
    -p 8002:8000 \
    -v /raid/wg25r/video_sql_v2/infra:/video_sql_infra:ro \
    -v video-sql-ec-cache:/epd_shared/cache \
    --entrypoint python3 \
    vllm/vllm-openai:qwen38-flash-next \
    /video_sql_infra/responses_epd_proxy.py \
    --host 0.0.0.0 \
    --port 8000 \
    --encoder-url http://qwen38-27b-fp8-epd-encoder:8000 \
    --pd-url http://qwen38-27b-fp8-epd-pd:8000 \
    --cache-dir /epd_shared/cache

Training clears the shared encoder cache at startup and after each batch's
rollouts finish. The proxy rejects cleanup while requests are active, resets
both servers' internal encoder caches, then removes the shared cache files.
VLLM_SERVER_DEV_MODE exposes the reset_encoder_cache endpoint on the private
project network. Model and sampling settings are unchanged.

Qwen/Qwen3-VL-Embedding-8B service:

docker run --name egolife-qwen3-vl-embedding-8b \
    --network video-sql-v2 \
    --gpus '"device=4"' \
    --shm-size=8g \
    -p 8013:8000 \
    -e HF_HOME=/hf_cache \
    -v /raid/huggingface:/hf_cache \
    -v /raid/wg25r/video_sql_v2:/workspace/video_sql_v2:ro \
    vllm/vllm-openai:qwen38-flash-next \
    Qwen/Qwen3-VL-Embedding-8B \
    --served-model-name qwen3-vl-embedding-8b \
    --runner pooling \
    --host 0.0.0.0 \
    --port 8000 \
    --gpu-memory-utilization 0.45 \
    --mm-processor-cache-gb 0 \
    --trust-remote-code \
    --allowed-local-media-path /workspace/video_sql_v2/data/pilot/clips \
    --renderer-num-workers 4 \
    --max-num-batched-tokens 32768 \
    --media-io-kwargs '{"video":{"video_backend":"qwen3_vl","backend":"torchcodec","fps":2,"num_frames":-1,"seek_mode":"approximate","num_ffmpeg_threads":4}}'

Stop after the run:

docker stop qwen38-27b-fp8-epd-proxy qwen38-27b-fp8-epd-encoder qwen38-27b-fp8-epd-pd egolife-qwen3-vl-embedding-8b

After debugging and log inspection, remove the stopped containers manually:

docker rm qwen38-27b-fp8-epd-proxy qwen38-27b-fp8-epd-encoder qwen38-27b-fp8-epd-pd egolife-qwen3-vl-embedding-8b
docker volume rm video-sql-ec-cache
