EgoLife baseline Qwen infrastructure (disaggregated encoder)

The launch configuration is implemented by infra/trace2skill_service.py for the egolife-baselines-* containers. Inspect current resource availability before starting services.

Service          Physical GPU(s)  Host endpoint                  Container
Prefill/decode   4,5 (TP=2)       http://127.0.0.1:8124           egolife-baselines-pd
Encoder          6                http://127.0.0.1:8125           egolife-baselines-encoder
Embedding        6                http://127.0.0.1:8114/v1        egolife-baselines-embedding
Responses proxy  none             http://127.0.0.1:8103/v1        egolife-baselines-proxy

The encoder and embedding services share GPU 6. The proxy accepts /v1/responses and /v1/chat/completions, primes each image or video input through the encoder, then forwards the original request to prefill/decode. ECExampleConnector transfers the encoded tensors through the shared tmpfs volume mounted at /epd_shared/cache: the encoder is ec_producer and prefill/decode is ec_consumer. Native sampled-video clip QA uses /v1/chat/completions through the same proxy.

Prefill/decode uses max-num-seqs 50. MTP drafts 3 tokens and has max_model_len 314573, matching the main model. SimpleCPUOffloadConnector uses 137438953472 bytes (128 GiB) per TP rank, 256 GiB total, with eager offload. This CPU KV cache is separate from the shared encoder-cache volume. The multimodal processor cache is 4 GiB on both prefill/decode and encoder; the embedding service retains its 0 GiB setting.

The training_free harness uses http://127.0.0.1:8103/v1 for Qwen and http://127.0.0.1:8114/v1 for embeddings. Each quality method runs 20 questions concurrently. SQL main and child investigation calls share each attempt's 60-call budget, followed by one forced final call.

Preparation

Run commands from /raid/wg25r/video_sql_trace2skill. Use the existing local image video-sql-vllm-epd:egolife-baselines for all four services. The image build recipe is infra/Dockerfile.baselines. The embedding container mounts /raid/videosql-video-artifacts and uses the qwen3_vl_uniform video loader on caption-interval cache clips. Model files must already be cached under /raid/huggingface because serving uses HF_HUB_OFFLINE=1.

Create the network and shared tmpfs volume once, if they do not already exist:

docker network create egolife-baselines

docker volume create \
    --driver local \
    --opt type=tmpfs \
    --opt device=tmpfs \
    egolife-baselines-ec

Create containers with the checked-in launcher

Run each command in its own foreground session; each remains attached to its service. Start the encoder before embedding on the shared GPU, and wait for all health checks below before starting clients. The launcher writes each exact Docker command to runs/egolife-baselines/services/<role>-command.json. Save service logs under that ignored run directory.

.venv_baselines/bin/python infra/trace2skill_service.py pd
.venv_baselines/bin/python infra/trace2skill_service.py encoder
.venv_baselines/bin/python infra/trace2skill_service.py embedding
.venv_baselines/bin/python infra/trace2skill_service.py proxy

Health checks and cache maintenance

curl --fail http://127.0.0.1:8124/health
curl --fail http://127.0.0.1:8125/health
curl --fail http://127.0.0.1:8114/health
curl --fail http://127.0.0.1:8103/health
curl --fail http://127.0.0.1:8103/v1/models

The proxy also implements POST /v1/responses/input_tokens using prefill/decode's /tokenize endpoint; this applies the model tokenizer/template and multimodal processor without model generation.

For manual encoder-cache cleanup, stop clients and wait for in-flight requests to finish before calling:

curl --fail -X POST http://127.0.0.1:8103/clear_encoder_cache

The proxy returns 409 if its requests are still active. Otherwise it resets the encoder caches on both encoder and prefill/decode, then removes the shared encoder-cache files. VLLM_SERVER_DEV_MODE=1 enables the required reset_encoder_cache endpoint.

Restart or replace existing containers

Stop clients first, then stop the four named services:

docker stop --timeout 60 egolife-baselines-proxy egolife-baselines-pd egolife-baselines-encoder egolife-baselines-embedding

For an unchanged restart, attach each command in its own foreground session. docker start reuses the saved container arguments:

docker start -a egolife-baselines-pd
docker start -a egolife-baselines-encoder
docker start -a egolife-baselines-embedding
docker start -a egolife-baselines-proxy

To change launch arguments, update infra/trace2skill_service.py, stop the services as above, inspect/save their logs, and remove the stopped containers before recreating them with the launcher. docker start does not apply changes made to the launcher:

docker rm egolife-baselines-proxy egolife-baselines-pd egolife-baselines-encoder egolife-baselines-embedding

Retain the named volume and /raid/huggingface mount for subsequent launches. After the run is finished, stopped containers can be removed manually with the same docker rm command.
