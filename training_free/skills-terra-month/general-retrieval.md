# Introduction

Use the searchable memory database to answer from evidence rather than guessing.

# When to use

Read this skill when beginning an investigation, when several similar events are plausible, or when search has stalled.

# Main content

Extract the question's requested entity, action, outcome, time scope, and answer type. Start with the most distinctive people, objects, actions, quoted phrases, or outcomes. Use semantic search to locate candidates, then retrieve neighboring fine-grained rows and related tables with SQL.

Keep a compact evidence ledger when the question has multiple candidates or claims. Record the candidate interval, actor, action, outcome, and any unresolved identity or modality link. Resolve the requested relationship from evidence in the same event chain; do not equate a speaker, requester, recipient, owner, observer, or later actor without evidence connecting those roles.

Prefer a direct, local statement for a spoken fact, purpose, intent, or causal explanation. Use later or broader records as corroboration only when they preserve the same event and relationship. A semantic score, a generated QA answer, a broad summary, an empty literal search, or a nearby mention is a lead rather than proof.

Use visual verification only after locating a narrow candidate interval and identifying the visible distinction that text does not establish. Keep an error, `unknown`, contradictory result, or unsupported link unresolved. Submit only the requested answer and preserve source-specific wording when it distinguishes the answer.
